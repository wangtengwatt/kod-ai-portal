# KOD 算力中心 MVP 部署说明

本次实现基于 `release/3.0` 后端和 KOD 客户端共享渲染层。数据库迁移全部使用独立的 `compute_*` 表；兼容迁移只会为早期 `compute_*` 表补字段，不会 `ALTER` 或 `DROP` 同事维护的存量业务表。唯一会写入旧表的业务动作，是用户主动购买卡时时在同一事务中扣减 `sys_user.balance`。

## 上线前必须完成

1. 先备份 `kod` 数据库。
2. 人工审查并执行 [`backend/src/main/resources/compute-center-schema.sql`](../backend/src/main/resources/compute-center-schema.sql)。脚本可重复执行，不包含测试商品和测试余额。
3. 在部署环境配置：

```dotenv
KOD_COMPUTE_ADMIN_EMAILS=2106784113@qq.com,289125266@qq.com,2180864364@qq.com,eudora@vn.com,3079793092@qq.com,2148521268@qq.com,468978441@qq.com,1696716866@qq.com
KOD_COMPUTE_KAI_STATION_DOMAINS=kai.com
KOD_CARD_HOUR_CNY_RATE=1.002
KOD_TRANSFER_REVIEW_THRESHOLD_CARD_HOURS=1000.000
KOD_COMPUTE_DELIVERY_SECRET=<至少32位生产随机值>
KOD_COMPUTE_PRIVATE_STORAGE_DIRECTORY=<私有加密证件目录>
KOD_COMPUTE_SCHEMA_INIT_ENABLED=false
KOD_COMPUTE_TEST_IDENTITY_ENABLED=false
KOD_COMPUTE_DEMO_SEED_ENABLED=false
```

管理员邮箱不是数据库角色字段：邮箱对应用户完成注册后，后端根据环境白名单实时授予算力中心管理员权限。修改白名单后需重启后端。

`KOD_COMPUTE_DELIVERY_SECRET` 用于 AES-GCM 加密 GPU 交付信息、节点 SSH 凭据和实名认证材料，并用于身份证指纹 HMAC。生产环境不可使用示例值；密钥丢失后历史密文无法解密，替换密钥前必须制定数据迁移方案。

## 推荐部署顺序

1. 执行建表脚本。
2. 注入上述环境变量并部署后端。
3. 部署 KOD 客户端/Web 端构建产物。
4. 八个管理员账号分别登录一次，确认“算力中心 → 运营管理”可见。
5. 管理员发放少量、带有效期的测试卡时。
6. 管理员创建固定 Token 套餐；供应方按“实名认证 → 入驻审核 → GPU 节点验机 → 商品审核”发布 GPU 测试商品。
7. 用小组买方账号完成套餐购买、GPU 预订、交付、到期结算和转让验收。

若建表脚本尚未执行，旧 API 人民币扣费会继续运行，算力中心页面接口会因缺表不可用。定时结算会安全跳过，不影响旧服务启动。

## MVP 计费边界

- 标准卡时汇率为 `1 卡时 = 1.002 CNY`；购买最少 `0.1` 卡时且只能按 `0.1` 的倍数购买。
- 购买卡时只支持人民币余额单向兑换，不支持卡时提现或兑回人民币。
- API 商品按固定套餐一次性扣卡时，输入与输出 Token 分开、永久有效，同模型多次购买分别 FIFO 扣减并汇总展示。一次请求即使超额也完整返回，余额降到 0，超额部分赠送；下一次请求前客户端拒绝。`request_id` 与日志 ID 双重幂等。
- 已纳入套餐市场且用户已购买过的模型不会因商品下架重新落回人民币扣费；未纳入套餐市场的模型保留原人民币计费。
- GPU 按预约时段冻结并结算，不读取 H100 实际利用率。开始前可取消并全额解冻；开始后用户不可自行取消。
- 卡时转让无偿。双方在同一中转站可转让；双方中转站 URL 都属于 `kai.com` 或其子域时可跨站转让。达到 `1000` 卡时先由管理员审核，再由接收方确认。
- 购买卡时永不过期；管理员测试赠送可设置有效期；转让后继承原卡时批次有效期。
- 同一身份证最多认证五个账号。正式认证和模拟认证状态隔离；`TEST_APPROVED` 只能产生明确标记为内测的节点和商品。拒绝或注销后 30 天自动删除姓名、证件号和证件文件。

## 验收检查

- 人民币充值、旧订单、旧自定义 OpenAI/Claude Key 与未开通模型调用行为不变。
- 并发重复 API 日志只产生一条 `compute_api_usage_charge` 和一笔卡时流水。
- 同一 GPU 商品的重叠预约不会超过 `gpu_count`。
- GPU 交付密文不能在数据库中直接还原，买方/供应方/管理员以外用户无法读取。
- 卡时账户汇总等于未过期批次可用额与冻结额之和。
- 算力计费的 API 日志仍进入原有 dashboard 聚合。

## 当前第一版限制

- 在公司 H100 管理能力接入前，GPU 只能按预约时间计费，不能自动验证机器在线率、任务实际运行时长或性能质量。
- KOD 会在下一次发送前主动追平中转站日志并预检套餐，但日志在上游生成存在延迟，因此“上一条刚结束、下一条立即发送”仍有竞态。要做到严格零竞态，必须把每个请求经过 KOD 可识别用户的网关代理并在响应结束时原子记账。
- 公共 API Key 被复制到 KOD 客户端之外后，客户端预检无法约束该调用；这不是客户端代码能解决的问题，正式上线必须隐藏公共 Key，并由平台网关代理请求。
- 当前 `LogSyncService` 的后台轮询状态仍是单实例设计；本机双账号串行验收可用，但正式多用户并发前应改成按用户隔离的 worker/任务队列。
- 内部通知中心没有短信、邮件或外部 IM 推送。

## 安全事项

仓库当前的 `application.yml`、`.env.example` 等存量配置包含数据库、Redis、邮件、支付或 JWT 默认凭据。这不是安全的生产配置方式。上线前必须轮换已暴露凭据、删除源码中的真实默认值，并只通过密钥管理系统或部署环境注入。本次未直接清除这些存量默认值，以免在未协调同事部署流程前中断旧功能。
