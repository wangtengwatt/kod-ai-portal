# kod-ai-portal 部署文档

基于 Docker Compose 部署 kod 官网的**前端（Nginx）**与**后端（Spring Boot）**两个容器。
MySQL 与 Redis 使用**外部已有实例**（不由 Compose 创建）。

---

## 一、架构

```
                 ┌─────────────────────────── 服务器 18.166.72.200 ───────────────────────────┐
   用户 ── :80 ──▶│  kod-frontend (Nginx)                                                        │
                 │    ├─ 托管前端静态资源（SPA，history 路由回退 index.html）                    │
                 │    └─ /api/ 反向代理 ──▶ kod-backend:8080                                     │
                 │                                                                               │
                 │  kod-backend (Spring Boot, :8080)                                             │
                 └──────────┬───────────────────────────┬────────────────────────────────────────┘
                            │                           │
                   MySQL 18.139.134.29:3306/kod   Redis 18.139.134.29:6379
                        （外部已有实例）              （外部已有实例）
```

- **前端**：`frontend/` → 多阶段构建（Node 构建 → Nginx 托管），对外 `:80`
- **后端**：`backend/` → 多阶段构建（Maven → JRE 运行），对外 `:8080`
- **数据库/缓存**：复用外部 MySQL 8 与 Redis 7，连接信息由 `.env` 注入

> 后端以 `SPRING_PROFILES_ACTIVE=prod` 运行，上述变量覆盖 `application.yml` 中的默认值。

## 五、首次部署步骤

> 前提：数据库 `kod` 已存在，且账号对其有读写权限。

```bash
# 1. 安装 Docker（如未安装）
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker ubuntu   # 重新登录后可免 sudo

# 2. 同步代码到服务器（本地执行）
rsync -az --delete \
  --exclude='.git/' --exclude='node_modules/' --exclude='frontend/dist/' \
  --exclude='backend/target/' --exclude='.env' \
  -e "ssh -i ~/.ssh/aws_18_141_198_68 -o IdentitiesOnly=yes" \
  ./ ubuntu@18.166.72.200:/data/kod-ai-portal/

# 3. 建表（首次，库为空时执行一次）
mysql -h18.139.134.29 -P3306 -uaiex_dev -p kod < backend/src/main/resources/schema.sql

# 4. 配置 .env（服务器上）
cd /data/kod-ai-portal
cp .env.example .env && vi .env      # 填写真实连接信息
echo "JWT_SECRET=$(openssl rand -hex 32)" >> .env   # 或手动填入

# 5. 构建并启动
sudo docker compose build
sudo docker compose up -d

# 6. 验证
curl http://localhost/                # 前端首页
curl http://localhost/api/health      # 反代到后端，redis 应为 UP
```

## 六、更新 / 重新部署

```bash
# 本地：同步最新代码
rsync -az --delete --exclude='.git/' --exclude='node_modules/' \
  --exclude='frontend/dist/' --exclude='backend/target/' --exclude='.env' \
  -e "ssh -i ~/.ssh/aws_18_141_198_68 -o IdentitiesOnly=yes" \
  ./ ubuntu@18.166.72.200:/data/kod-ai-portal/

# 服务器：重建并滚动更新
cd /data/kod-ai-portal
sudo docker compose build
sudo docker compose up -d            # 仅重建有变化的服务

# 只更新某一个服务
sudo docker compose up -d --build backend
sudo docker compose up -d --build frontend
```

## 七、常用运维命令

```bash
cd /data/kod-ai-portal
sudo docker compose ps                # 查看状态
sudo docker compose logs -f backend   # 跟随后端日志
sudo docker compose logs -f frontend  # 跟随前端日志
sudo docker compose restart backend   # 重启后端
sudo docker compose down              # 停止并移除容器（保留镜像）
sudo docker compose up -d             # 启动
```

容器均配置 `restart: unless-stopped`，服务器重启后会自动拉起。

## 九、故障排查

| 现象 | 排查方向 |
| --- | --- |
| 前端 502 / `/api` 报错 | 后端未就绪：`docker compose logs backend`；确认 backend 容器 Up |
| 后端启动即退出 | 看日志是否 DB/Redis 连接失败；确认 `.env` 与网络连通（`nc -z 18.139.134.29 3306`） |
| 接口 500 且提示表不存在 | kod 库未建表：执行第五步的建表 SQL |
| 端口冲突 | 确认宿主机 80 / 8080 未被占用（`sudo ss -tlnp | grep -E ':80|:8080'`） |
| 外网打不开但本机正常 | AWS 安全组是否放行 80/tcp |

## 十、备注

- 数据库与 Redis 为**外部共享实例**，请勿在部署脚本中对其做破坏性操作（DROP/FLUSH）。
- 后端 Redis 使用 `kod:token:{userId}` 命名空间缓存登录 token；数据库仅使用 `kod` 库。
- 如需绑定域名 `kod.kai.com`，将其 A 记录指向 `18.166.72.200`，并在 Nginx 增加 `server_name` 与 HTTPS（证书）配置即可。
