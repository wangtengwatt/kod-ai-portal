# AI 中转站接口文档

## 1. 说明

- 服务模块：AI 中转站网关
- 调用方：Kod 客户端 / 官网后端 / 联调测试客户端
- baseUrl：`https://ai.kaiweb.net`
- 内部路径：`/v1/**`
- 协议风格：OpenAI Chat Completions 兼容接口
- 鉴权方式：`Authorization: Bearer <apiKey>`
- 示例模型：`glm-5`

### 1.1 Base URL

| 环境 | baseUrl | 说明 |
| --- | --- | --- |
| 线上 | `https://ai.kaiweb.net` | 当前 AI 中转站访问地址 |

完整请求地址拼接规则：

```text
{baseUrl} + /v1/...
```

示例：

```text
https://ai.kaiweb.net/v1/models
https://ai.kaiweb.net/v1/chat/completions
```

### 1.2 请求头

| Header | 必填 | 说明 |
| --- | --- | --- |
| `Authorization: Bearer <apiKey>` | 是 | AI 中转站 API Key |
| `Content-Type: application/json` | POST 接口必填 | JSON 请求体 |

> 安全提示：接口文档、代码仓库、HTTP 测试文件中不要提交真实 API Key。下方示例统一使用 `<apiKey>` 占位。

### 1.3 接口一览

| 接口 | 方法 | 鉴权 | 功能 |
| --- | --- | --- | --- |
| `/v1/models` | `GET` | Bearer API Key | 查询当前 API Key 可访问的模型列表 |
| `/v1/chat/completions` | `POST` | Bearer API Key | 发起对话补全请求 |

### 1.4 通用错误

实际错误结构以中转站返回为准。常见错误场景如下：

| HTTP 状态 | 含义 | 触发条件 |
| --- | --- | --- |
| `401` | 未授权 | 缺少 `Authorization`、API Key 无效或已禁用 |
| `403` | 无权限 | API Key 无权访问指定模型或渠道 |
| `404` | 资源不存在 | 模型不存在或路径错误 |
| `429` | 请求过多 | 触发限流或额度不足 |
| `500` | 服务端异常 | 中转站或上游模型服务异常 |

## 2. 查询模型列表

### `GET /v1/models`

查询当前 API Key 可访问的模型列表。客户端可用该接口判断模型是否可用，并展示模型选择列表。

#### 请求

无请求体。

```bash
curl -i "https://ai.kaiweb.net/v1/models" \
  -H "Authorization: Bearer <apiKey>"
```

#### 响应

OpenAI 兼容模型列表响应通常如下：

```json
{
  "object": "list",
  "data": [
    {
      "id": "glm-5",
      "object": "model",
      "created": 0,
      "owned_by": "system"
    }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `object` | string | 固定或兼容值，通常为 `list` |
| `data` | array | 模型列表 |
| `data[].id` | string | 模型 ID，调用聊天接口时传入 `model` |
| `data[].object` | string | 资源类型，通常为 `model` |
| `data[].created` | number | 创建时间戳；中转站可能返回 `0` 或上游值 |
| `data[].owned_by` | string | 模型归属方或兼容字段 |

#### 错误码

| HTTP 状态 | 含义 |
| --- | --- |
| `401` | API Key 缺失、无效或已禁用 |
| `429` | 触发限流或额度不足 |
| `500` | 中转站或上游服务异常 |

#### 服务侧流程

1. 校验 `Authorization` 请求头。
2. 根据 API Key 查询可用渠道、模型和额度。
3. 组装 OpenAI 兼容模型列表。
4. 返回可访问模型清单。

## 3. 创建聊天补全

### `POST /v1/chat/completions`

发起 OpenAI 兼容的 Chat Completions 请求。请求体至少需要包含 `model` 和 `messages`。

#### 请求

```json
{
  "model": "glm-5",
  "messages": [
    {
      "role": "user",
      "content": "Reply exactly: GLBWinTK OK"
    }
  ],
  "temperature": 0,
  "max_tokens": 20
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `model` | string | 是 | 模型 ID，例如 `glm-5` |
| `messages` | array | 是 | 对话消息列表 |
| `messages[].role` | string | 是 | 消息角色，常用值：`system`、`user`、`assistant` |
| `messages[].content` | string | 是 | 消息内容 |
| `temperature` | number | 否 | 采样温度；`0` 表示更稳定、更确定的输出 |
| `max_tokens` | number | 否 | 最大输出 token 数 |
| `stream` | boolean | 否 | 是否流式返回；未传时通常为非流式 |

请求示例：

```bash
curl -i "https://ai.kaiweb.net/v1/chat/completions" \
  -H "Authorization: Bearer <apiKey>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "glm-5",
    "messages": [
      {
        "role": "user",
        "content": "Reply exactly: GLBWinTK OK"
      }
    ],
    "temperature": 0,
    "max_tokens": 20
  }'
```

#### 响应

非流式响应通常如下：

```json
{
  "id": "chatcmpl-xxx",
  "object": "chat.completion",
  "created": 1784193720,
  "model": "glm-5",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "GLBWinTK OK"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 15,
    "completion_tokens": 5,
    "total_tokens": 20
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 本次补全请求 ID |
| `object` | string | 对象类型，通常为 `chat.completion` |
| `created` | number | 服务端创建时间戳 |
| `model` | string | 实际使用的模型 |
| `choices` | array | 候选回复列表 |
| `choices[].index` | number | 候选序号 |
| `choices[].message.role` | string | 回复角色，通常为 `assistant` |
| `choices[].message.content` | string | 回复内容 |
| `choices[].finish_reason` | string | 结束原因，例如 `stop`、`length` |
| `usage.prompt_tokens` | number | 输入 token 数 |
| `usage.completion_tokens` | number | 输出 token 数 |
| `usage.total_tokens` | number | 总 token 数 |

#### 错误码

| HTTP 状态 | 含义 | 触发条件 |
| --- | --- | --- |
| `400` | 请求参数错误 | 缺少 `model`、`messages` 为空、JSON 格式错误等 |
| `401` | API Key 无效 | 缺少或非法的 Bearer API Key |
| `403` | 模型无权限 | 当前 API Key 无权访问指定 `model` |
| `404` | 模型不存在 | 指定模型未配置或不可用 |
| `429` | 限流 / 额度不足 | 请求频率过高、额度不足或渠道限流 |
| `500` | 服务端异常 | 中转站或上游模型服务异常 |

#### 服务侧流程

1. 校验 `Authorization` 请求头和 API Key。
2. 校验请求体中的 `model`、`messages` 等参数。
3. 根据模型和渠道配置选择可用上游。
4. 转发请求到上游模型服务。
5. 将上游响应转换为 OpenAI 兼容格式。
6. 返回补全结果，并记录用量。

## 4. 联调流程

1. 使用 API Key 查询模型列表：

```bash
curl -i "https://ai.kaiweb.net/v1/models" \
  -H "Authorization: Bearer <apiKey>"
```

2. 确认响应中存在 `glm-5`。

3. 使用 `glm-5` 发起聊天补全：

```bash
curl -i "https://ai.kaiweb.net/v1/chat/completions" \
  -H "Authorization: Bearer <apiKey>" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "glm-5",
    "messages": [
      {
        "role": "user",
        "content": "Reply exactly: GLBWinTK OK"
      }
    ],
    "temperature": 0,
    "max_tokens": 20
  }'
```

4. 验证返回内容：

```text
GLBWinTK OK
```

## 5. 客户端接入建议

- 客户端配置中转站地址时，baseUrl 填 `https://ai.kaiweb.net`。
- 聊天接口路径固定使用 `/v1/chat/completions`。
- 模型 ID 使用 `/v1/models` 返回的 `data[].id`。
- 不要在前端源码、日志、文档或截图中暴露真实 API Key。
- 非流式联调用 `stream=false` 或不传 `stream`；需要逐字输出时再启用 `stream=true`。
